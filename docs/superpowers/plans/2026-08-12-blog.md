# HangingRabbit's Blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Quarto static site at `meghanadhpulivarthi.github.io` holding CS336 writeups, with a year-grouped archive and post layout modeled on sebastianraschka.com.

**Architecture:** Quarto website project. Posts are static `.qmd` markdown in `posts/<project>/<date>-<slug>/index.qmd`, one folder per post so images sit beside their text. Two listing pages read the same `posts/**` glob: the homepage shows the five most recent, `blog.qmd` renders the full archive through a custom EJS template that inserts a heading each time the year changes. Styling is one hand-written `styles.css` over a paired light/dark Bootstrap theme. Publishing is a manual script to a `gh-pages` branch.

**Tech Stack:** Quarto (standalone binary via Homebrew), Bootstrap themes `litera`/`darkly`, EJS listing template, GitHub Pages. No Python environment, no Ruby, no Node, no build step beyond `quarto render`.

## Global Constraints

- Repo root is `~/Development/meghanadhpulivarthi.github.io`; every path below is relative to it.
- Site title is exactly `HangingRabbit's Blog`. Author byline is exactly `Meghanadh Pulivarthi`.
- Site URL is `https://meghanadhpulivarthi.github.io` (no path suffix — the repo is named after the user).
- Date display format is `MMM D, YYYY` (e.g. `Aug 12, 2026`) everywhere it appears.
- No absolute paths in any committed file, including `publish.sh`.
- Bash scripts start with `set -euo pipefail`, declare config variables at the top, quote all variable expansions, and must run from any working directory.
- Posts do not execute code. No `jupyter` engine, no Python dependency.
- `_site/` and `.quarto/` are never committed.
- Every post's front matter must include `title`, `date`, `categories`, and `description`. The archive is unreadable without `description`.
- CS336 course policy (`~/Development/assignment1-basics/CLAUDE.md`) forbids AI-authored assignment code. Post code blocks are short verbatim quotes of code the author already wrote, never newly generated tokenizer/model implementations, and never a complete working solution.

````markdown
---
title: "What BPE actually merges"
date: 2026-08-12
categories: ["CS336 Note"]
description: "Byte-pair encoding is usually described as merging the most frequent pair. Two details do most of the work: pretokenization decides which pairs are even visible, and ties have to be broken deterministically."
---

Byte-pair encoding gets described in one line: repeatedly merge the most frequent
adjacent pair of tokens. That line is true and it hides the two details that determine
what your vocabulary actually looks like.

## Pretokenization decides what is adjacent

BPE never sees your corpus as one long string. The text is first split into
pretokens — roughly words, with leading whitespace attached — and merges are only ever
counted *within* a pretoken, never across a boundary.

This is a modeling decision disguised as an implementation detail. If pairs could merge
across boundaries, nothing stops a single token from spanning `the` and the space and
`cat`, and common phrases would collapse into single tokens. The boundary is what
guarantees tokens stay word-shaped.

So the frequency count is not over the corpus. It is over pairs inside pretokens,
weighted by how often each pretoken occurs. A pretoken appearing 40,000 times
contributes 40,000 to each of its internal pairs, which is why the merge order is
dominated by high-frequency function words early on.

```{mermaid}
%%| label: fig-boundaries
%%| fig-cap: "Pairs are counted inside pretokens only. The dashed edge is never a candidate."
flowchart LR
  subgraph P1["pretoken: ' the'"]
    A["' t'"] --- B["'h'"] --- C["'e'"]
  end
  subgraph P2["pretoken: ' cat'"]
    D["' c'"] --- E["'a'"] --- F["'t'"]
  end
  C -.- D
```

## Ties are common, and the tie-break is part of the spec

Early in training, the counts are enormous and distinct. Later, once the frequent
structure is used up, many pairs sit at the same low count — often at 1. With a vocabulary
of tens of thousands of merges, ties are not an edge case, they are most of the tail.

An arbitrary tie-break makes training non-reproducible: the same corpus yields a
different vocabulary on each run, and a tokenizer that disagrees with the one your
checkpoint was trained under is silently broken. So the rule has to be deterministic, and
it is chosen rather than discovered:

```python
best_pair = max(byte_pairs.items(), key=lambda x: (x[1], x[0]))[0]
```

The key is a tuple, so Python compares count first and only falls through to the pair
itself when counts are equal. Because these are `bytes` tuples, that fallthrough is a
lexicographic comparison, and `max` takes the *greatest* pair. Nothing about the data
prefers the lexicographically larger pair — it is simply a rule both the trainer and any
reimplementation can agree on.

Formally, with $c(p)$ the count of pair $p$:

$$
p^\star = \operatorname*{arg\,max}_{p} \; \big( c(p),\, p \big)
$$

where the maximum is over the lexicographic order on the tuple. Write it that way and the
tie-break stops looking like a detail and starts looking like what it is: part of the
definition of the algorithm.

## What I took from this

The one-line description of BPE is a description of the *loop*, not of the algorithm. The
vocabulary you get is determined about as much by where you drew the pretoken boundaries
and how you ordered equal counts as by the merge rule everyone quotes.
````

- [ ] **Step 2: Create `ejs/archive.ejs`**

Quarto passes the template an `items` array, already sorted by the listing's `sort` key.
The template walks it in order and opens a new year heading whenever the year changes.

Dates are read with UTC getters and formatted with `timeZone: "UTC"`. This matters: a
date-only string like `2026-01-01` parses as UTC midnight, and formatting it in a
timezone behind UTC would render it as December 31 of the previous year — putting a post
under the wrong year heading.

```ejs
<% let currentYear = null; %>
<% for (const item of items) { %>
  <% const parsed = item.date ? new Date(item.date) : null; %>
  <% const year = parsed ? parsed.getUTCFullYear() : "Undated"; %>
  <% if (year !== currentYear) { %>
    <% if (currentYear !== null) { %>
      </div>
    <% } %>
    <% currentYear = year; %>
    <h2 class="archive-year"><%= year %></h2>
    <div class="archive-year-group">
  <% } %>
  <div class="archive-row">
    <span class="archive-date"><%= parsed ? parsed.toLocaleDateString("en-US", { month: "short", day: "numeric", year: "numeric", timeZone: "UTC" }) : "" %></span>
    <span class="archive-category"><%= (item.categories && item.categories[0]) || "" %></span>
    <a class="archive-title" href="<%= item.path %>"><%= item.title %></a>
    <div class="archive-description"><%= item.description || "" %></div>
  </div>
<% } %>
<% if (currentYear !== null) { %>
  </div>
<% } %>
```

```markdown
# HangingRabbit's Blog

Quarto site published to GitHub Pages at <https://meghanadhpulivarthi.github.io>.

## Writing a post

1. `mkdir -p posts/<project>/YYYY-MM-DD-slug/images`
2. Create `index.qmd` in that folder with front matter — `title`, `date`,
   `categories`, `description` are all required.

3. Add a navbar entry in `_quarto.yml`.

The homepage and archive glob `posts/**` and pick up new projects with no changes.
```
